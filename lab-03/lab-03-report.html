1. Aim & Objectives

To transform basic CRUD operations into an enterprise-ready, stateless RESTful API using Express.js and SQLite. Key focus areas:

  • Implement resource-centric routing with noun-based paths (/books) and appropriate HTTP action verbs (GET, POST, PUT, DELETE).
  • Add dynamic query parameter handling on GET /books: partial title search (search_q with LIKE ?), column sorting (order_by), sort direction (order=ASC|DESC), pagination (limit, offset), and price range filtering (min_price, max_price).
  • Enforce strict request body validation on POST /books, rejecting missing mandatory fields or non-numeric prices with 400 Bad Request and structured JSON error responses.
  • Adhere to REST standards for HTTP response status codes: 200 OK, 201 Created, 400 Bad Request, and 404 Not Found.
  • Prevent SQL Injection by implementing parameterized SQL queries with ? placeholders across all endpoints.
  • Diagnose and resolve common backend defects (port conflict, bad imports, schema typos, and missing await).

// GET /books: Search, Sorting, Filtering, and Pagination
app.get('/books', async (req, res) => {
  const { search_q = '', order_by = 'id', order = 'ASC', limit = 10, offset = 0,
          min_price = 0, max_price = 1000000 } = req.query;

  const allowedCols = ['id', 'title', 'author', 'price', 'pages'];
  const sortCol = allowedCols.includes(order_by) ? order_by : 'id';
  const sortOrder = order.toUpperCase() === 'DESC' ? 'DESC' : 'ASC';

  const query = `
    SELECT * FROM book
    WHERE title LIKE ? AND price BETWEEN ? AND ?
    ORDER BY ${sortCol} ${sortOrder}
    LIMIT ? OFFSET ?;
  `;
  const books = await db.all(query, [`%${search_q}%`, min_price, max_price, limit, offset]);
  res.status(200).json(books);
});

// POST /books: Strict Input Validation & 201 Response
app.post('/books', async (req, res) => {
  const { title, author, price, pages } = req.body;
  if (!title || typeof title !== 'string' || !title.trim()) {
    return res.status(400).json({ message: "Validation Error: 'title' is required." });
  }
  if (!author || typeof author !== 'string' || !author.trim()) {
    return res.status(400).json({ message: "Validation Error: 'author' is required." });
  }
  if (price === undefined || isNaN(Number(price)) || Number(price) < 0) {
    return res.status(400).json({ message: "Validation Error: 'price' must be a valid number." });
  }

  const result = await db.run(
    `INSERT INTO book (title, author, price, pages) VALUES (?, ?, ?, ?);`,
    [title.trim(), author.trim(), Number(price), Number(pages) || 100]
  );
  res.status(201).json({ message: 'Book Added Successfully', bookId: result.lastID });
});

5. Debugging Exercise: Defects & Solutions

Defect 1: Port Conflict (EADDRINUSE)
Root Cause: Port 3000 was already bound by another background Node process.
Solution: Used const PORT = process.env.PORT || 3000 and terminated the locking process with PowerShell: Stop-Process -Id <PID> -Force.
Defect 2: Wrong Import Path
Root Cause: Relative path ./database could not resolve.
Solution: Imported { open } directly from sqlite and bound to path.join(__dirname, 'books.db').
Defect 3: Table-Name Typo
Root Cause: DDL defined book while routes queried plural books, causing SQLITE_ERROR: no such table: books.
Solution: Standardized table name to book across all SQL statements.
Defect 4: Missing `await` Keyword
Root Cause: Calling async database operations without await dispatched empty responses prematurely.
Solution: Marked handlers as async and strictly awaited all query executions.

7. Viva Voce Questions & Detailed Answers

Q1: Difference between Query Parameter and Path Parameter?
Path parameters (e.g. /books/:bookId) pinpoint a specific resource entity in the URI hierarchy. Query parameters (e.g. /books?order_by=price&limit=5) appear after the ? symbol to filter, sort, or paginate the collection without changing entity identity.
Q2: What does "stateless" mean in REST architecture?
Every request from client to server must contain all of the information necessary to understand and complete the request. The server does not store any client session context between requests.
Q3: Which status code for bad input vs a missing record?
400 Bad Request is used for malformed or failing client input validation. 404 Not Found is used when the request syntax is valid but the target resource ID does not exist in the database.
Q4: Why use parameterized queries (?) against SQL injection?
Placeholders separate the SQL query structure from user input. The database treats parameter values strictly as data literals, making it impossible for user input to execute arbitrary SQL commands.
